# Held-out quality/conflict protocol (local-only scaffold)

`heldout_quality_conflict_protocol.py` is a reproducible evidence scaffold for
the memory-first core. It evaluates only structured, bounded **fact
selection** from two operator-supplied JSON runs. It never starts Ollama,
calls a model/embedding/provider, accesses a network, or judges a
natural-language answer.

The v1 fixture is deliberately synthetic and deterministic:

- 20 delayed-recall cases: one older target and eight distractors after a
  fixed 64-turn delay, with a three-fact budget;
- 50 conflicting-evidence cases: one authoritative fact, two contradictory
  facts and one distractor, with a two-fact budget.

The fixture, scoring contract and materialized corpus are bound by canonical
SHA-256 values in
[`fixtures/quality-conflict-heldout-v1/manifest.json`](fixtures/quality-conflict-heldout-v1/manifest.json).
A submitted run separately binds its policy object with `policy_sha256` and
must identify that exact corpus. The scorer rejects a changed fixture,
scoring policy, corpus, case set, unknown fact ID, duplicate, over-budget
selection, missing result, or mismatched hash.

## What the protocol measures

For a supplied baseline and candidate on the same frozen corpus and per-case
budget, it reports:

| Metric | Exact definition | Roadmap goal only |
|---|---|---:|
| Delayed target-selection rate | Fraction of delayed cases where the older target appears in `selected_fact_ids`. | Candidate minus baseline ≥ 15 percentage points |
| Conflict-fact rate | Fraction of conflict cases whose bounded selection includes at least one fact marked contradictory. | Candidate ≤ 2% |
| Authoritative-answer rate | Fraction of conflict cases whose structured `answer_fact_id` is authoritative. | Diagnostic only; no release target here |

Those are prospective gates for this named synthetic protocol. There is **no
empirical result checked in**: without a completed baseline run and candidate
run, the protocol is only a scaffold and it must not be described as a
quality result.

## Local use

```powershell
python benchmarks\heldout_quality_conflict_protocol.py --describe

python benchmarks\heldout_quality_conflict_protocol.py `
  --init-run .\baseline.run.json --role baseline
python benchmarks\heldout_quality_conflict_protocol.py `
  --init-run .\candidate.run.json --role candidate
```

The templates deliberately fail scoring. An operator completes them with a
real policy object and canonical policy hash, every bounded selection, and
the required attestations. Then score explicit local files only:

```powershell
python benchmarks\heldout_quality_conflict_protocol.py `
  --baseline-run .\baseline.run.json `
  --candidate-run .\candidate.run.json `
  --json .\quality-conflict-report.json `
  --markdown .\quality-conflict-report.md
```

No run input is generated by the tool. The JSON report retains hashes and
aggregate scores, while the Markdown report intentionally omits raw fact
selections and full policy configuration.

## Held-out governance boundary

The repository fixture is reproducible, so its presence here is not a claim
that it is secret or blind. To call a result a held-out observation, the
operator must freeze the fixture/scoring hashes before policy tuning, provide
the identical corpus to both sides, keep the gold relationship unavailable to
the policy author, and use an independent evaluator. The run schema requires
an explicit `true` attestation for those conditions plus `no_model_calls` and
`no_remote_io`; it cannot prove that a human statement is true.

For a genuinely blind external evaluation, place a new versioned fixture
bundle under independent access control and record its hashes in a new
protocol version. Do not rewrite this v1 fixture or its scoring target after
observing candidate results.

This protocol makes no claim about model answer quality, general semantic
recall, production conflict handling, prompt-injection resistance, latency,
throughput, or superiority over another framework.

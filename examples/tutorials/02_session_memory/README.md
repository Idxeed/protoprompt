# Урок 2: память сессии и сжатие

Длинный диалог сжимается в короткие блоки и попадает в хранилище.

## Запуск

```bash
python examples/tutorials/02_session_memory/main.py
```

Работает офлайн — сеть и ключи не нужны.

## Что показывает

1. `Pipeline` решает, когда сжимать (`should_compress`), и запускает
   стратегию.
2. `HeuristicStrategy` делит диалог на области: `head` (начало),
   `tail` (конец), `important` (важные реплики из середины).
3. Блоки-выжимки попадают в стор под именем `session_c1`.
4. Память сессии можно найти по смыслу через обычный `store.query` —
   так её потом подхватывает `ContextBuilder`.

## Идея для эксперимента

- Попробуйте `LLMSummaryStrategy(model="llama3.1", window_size=6)` вместо
  `HeuristicStrategy()` — она зовёт LLM, поэтому с FakeLLM вернёт заглушку.
- Уменьшите `compress_every_n` до 4 и посмотрите, как меняются блоки.

Полное объяснение — в [уроке 2 документации](../../../docs/ru/tutorials/02-session-memory.md).
